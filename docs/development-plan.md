# Wuwa Draw 現行規格與開發計畫

> 唯一現行產品與實作規格；[詞彙](../CONTEXT.md)、[隔離決策](adr/0001-streamer-isolation.md)、[取消決策](adr/0002-cancellation-compensation.md)。本文為產品目標，非完成宣告；issue #8 的本機窄路徑及其限制見[實測證據](issue-8-evidence.md)。根目錄為本 repository 根目錄，名稱確定為 Wuwa Draw。

## 1. 產品邊界與權限

Wuwa Draw 以鳴潮為主題，不是 Kin 品牌。單站多主播，以經驗證的 Discord ID 識別主播；共用登入身分，不共用分數。場次、報名、抽選、設定與權限均依主播環境隔離。不同主播可並行活動，但共用基礎設施及免費額度。

平台管理者指定、核准及停用主播，並查看不含觀眾私有明細的服務用量；不開放主播申請按鈕、API、佇列或通知。平台角色不能代抽、改分、結算或查看其他主播私有報名名單與聯絡資料。僅主播本人操作自己的環境；不支援小幫手或代理。未核准者登入不取得主播資格。管理者若同時為主播，只能操作自己的主播環境。

**負責人已確認（#2，政策而非實作完成）：**初始管理者由伺服器配置其 Discord ID 指定；未配置時沒有人取得管理權。只有經驗證且符合配置 ID 的管理者可進入非公開、受權限限制的管理頁，以 Discord ID 指定及核准主播；未核准者不是主播，不提供公開申請。伺服器配置若遺失或需更換，須由有權管理伺服器配置者修正配置，不能由公開流程恢復。

決策比較：伺服器配置不暴露公開自助入口，恢復依賴配置管理權限，操作需人工維護配置；公開申請或自助流程會增加暴露面與審核操作，且違反已確認的不開放申請邊界。受限管理頁方便日常核准，但必須在伺服器端驗證管理者身分與權限，不能只依頁面隱藏保護。

停用後禁止開新場、新報名及抽選；原主播仍可讀取本場必要資料，選擇正常結束結算或取消恢復。停用不自動收尾、不清除分數或歷史；寫入提交時須核對狀態。**負責人已確認（#3，政策而非實作完成）：**管理者須明確重新核准已停用主播，才恢復主播資格；保留全部既有資料及未完成場次，不自動開場。有未完成場次時，主播接回該場且不得再開新場；仍遵守每主播至多一場未完成的限制。

## 2. 場次、資格與操作

- 每主播至多一場未結束場次，`open`、`paused` 均占位；正常結算或取消恢復**全部完成**才釋放。不同主播互不阻擋。開場限制及狀態由伺服器和資料庫保護。
- 持續接受報名，不強制倒數。暫停只停止新報名，既有候選人仍可抽，未中者可自行退出；恢復仍是同場。暫停與報名以原子提交先後判定。
- 關頁、登出、斷線或逾時不自動結束、取消或結算；原本 open 離線仍收報名，主播重新登入接回本場和已保存結果。觀眾不必在線，不做心跳。
- 開場鎖定群限制及所有影響資格或機率的規則版本，暫停也不得修改；環境預設變更不影響本場。要改本場規則須取消並完成恢復，再開新場；所有人重新報名、必要時重新查群，序號從 1 重排，不搬名單或舊狀態。
- 觀眾 Discord 登入；不收 email、遊戲 UID、遊戲伺服器或角色名稱。群限制可選、各環境獨立；啟用時於報名檢查指定 guild 成員資格，只檢查當時：之後退群本場仍有效，下場重新檢查。`pending` 提示完成入群 screening；未加入提示邀請和重查；授權失效、429、故障等顯示可重試錯誤，不誤稱未加入亦不放行。Discord `identify` 與需要時的 `guilds.members.read`／指定 guild member endpoint 可無 bot 檢查；上線前驗證官方行為。
- 成功報名者一場一筆，首次成功序號從 1 開始且不因他人退出或中獎重排。未中者可自行退出，保留原分、不加不扣，同場不可重報；退出先提交則不在後續抽選，中獎先提交則退出拒絕。不能代他人退出；不做黑名單、主播手動剔除或個人權重歸零介面/API，也不接受指定個別排除的抽選參數。
- 每位主播固定入口，無公開目錄或搜尋；無活動顯示目前未開放。所有報名、退出等寫入綁定所見的確切場次及規則版本，舊場或舊規則請求拒絕並提示重新確認，包含 OAuth 返回後；不得默投新場。

## 3. 抽選、分數與終點

每抽以伺服端一致的候選快照為準，之後成功報名者參加下一抽。空候選或失敗不構成有效抽選。安全亂數選一人；結果、候選快照與 winner 分數立即歸零須一致提交，winner 同場不再中。此結果不取決於實際參加或聯絡成功；聯絡失敗不恢復、不自動重抽。重試同一抽選冪等鍵回傳既存結果，不重抽；不同鍵並發亦不可重複選中、漏寫或重設錯誤。動畫只揭曉已持久化結果。

分數依主播與觀眾獨立，存儲值真實封頂 0..10，不保留可抵銷未來扣分的隱藏累積。正常結束且至少完成一次有效抽選時，只結算一次：

| 本場觀眾狀態 | 分數效果 |
| --- | --- |
| 中獎 | 抽中立即歸零，結束不加分 |
| 結束前成功報名、未中、未退出 | 加 1，最高 10；即使最後一抽後才報名、從未進候選快照亦加 |
| 成功報名後自行退出 | 不加不扣，保留原分 |
| 該主播環境有分但整場未報名 | 扣 1，最低 0；包括不在本場名單的歷史觀眾 |

無有效抽選而正常結束，全員不加不扣；空抽及失敗請求不算有效抽選。時間流逝、登出、離線及歷史清理本身不扣分。報名與結束的提交先後決定資格，結束先提交則報名拒絕。

尚未結束場次可取消：以開場前分數為基準，只補償本場造成的分數變更；本場新觀眾原本為 0 仍為 0。保留報名、抽選及候選歷史，標記取消、不計有效成績；不回退帳號、設定或其他主播。取消不作正常結算或缺席扣分。正常結束與取消互斥；已結束結算不得取消，已取消不得結算；重試與延遲請求不能重做終點或影響新場。開始基準須在開放前安全建立；可用其他等價設計，但必須證明同等恢復和並發安全。

### 統一抽選公式

對 N 個候選者，`P(i) = 0.5/N + 0.5*w_i/sum(w)`，其中 `w_i = (1 + 0.4*score_i) * (1 + 0.2/(1 + (ordinal_i-1)/50))`。序號為本場不可變原始報名序號，從 1 起。全站公式與數值已鎖定，主播不可自訂；開場保存適用規則版本。公平池 50% 不受權重影響。不得自行調參；如需變更須另獲確認。

解析核算而非模擬：500 位同分候選者，序號 1、51、101、500 的單抽機率約 0.2145%、0.2049%、0.2018%、0.1971%；不含早到倍率的對照中，450 位零分及 50 位滿分候選者分別約 0.1714%、0.4571%。尚未執行多場模擬或容量實測，不得編造結果。

## 4. 可見性與聯絡

公開僅顯示人數、規則及 winner 顯示名稱；公開 API 不得傳送私有欄位後以 CSS 隱藏。**顯示名稱政策（已核准；本機合成實作）**：報名時以本場指定 Discord 群暱稱、Discord 全域顯示名稱、打碼 username 依序取用；不限群不查群或增加 scope。打碼按 Unicode code point：至少 5 個保留首尾各一，其餘固定 `***`；1–4 個只保留首一及 `***`；無資料顯示「中獎者」。打碼降低曝光但非匿名，仍可能被推知。群暱稱來自綁定場次、群、觀眾與有效成員資格 proof 的伺服器資料，報名時固定名稱及來源快照；後續改名不回寫舊報名及已揭曉結果，舊資料無名稱顯示「中獎者」，不憑空回填。公開 API 不傳完整 username 或打碼前字串。登入觀眾僅可讀自己在該環境的報名狀態、序號、分數及目前單抽機率；機率附候選資料更新時點，說明隨名單變化且非整場中獎保證。主播本人可讀自己環境的完整名單、結果與聯絡資訊；平台管理者無跨主播私有資料讀取權。

主播本人透過 Discord 私訊聯絡，頁面提供聯絡入口和 username／ID 複製備援；提醒觀眾留意私訊。不保證 deeplink、雙方可私訊或送達，網站不代發。不要把取得帳號資訊當成完成聯絡。

**負責人已確認（#5，政策而非實作完成）：**上線隱私告知須說明處理必要的 Discord 身分及報名、抽選等資料；分數按主播環境獨立，公開僅人數、規則及 winner 顯示名稱。詳細報名、抽選、候選及聯絡歷史依第 5 節在正常結算或取消恢復全部完成後保留 90 天；分數與正確性所需最小冪等資料持續保留。公開人工聯絡信箱為 contact@makinoworks.com，資料權利請求由人工處理，不提供自助刪除 UI、API 或佇列。正式上線前須確認適用法律要求及告知內容；本決定不表示法律審查或合規已完成。

## 5. 技術約束與資料契約

- Cloudflare Workers Static Assets + 同源 Worker API + D1；靜態資產直接交 Assets，API/OAuth 經 Worker。全程免費方案為硬限制，不升級、不啟用付費服務；GitHub 僅存原碼，並非部署授權。額度為帳戶共用且可能耗盡造成服務中斷，不承諾獨立資源或可用性；實作前查最新官方額度並實測。避免高頻輪詢，量測讀寫及監控用量。
- OAuth server-side authorization code 交換，驗證 state；PKCE 等依 Discord 正式文件驗證支援後採用，精確 redirect URI。secret 不進 repo、前端或日誌；session 使用 Secure、HttpOnly、SameSite cookie 與 CSRF 防護。最小 scope：`identify`，群檢查時另需 `guilds.members.read`；不索取 email。token 受限保護並只保留必要時間。
- 邏輯資料至少區分共用 Discord 身分、主播環境、以 `(streamer, viewer)` 隔離的分數、場次與鎖定規則、報名／不可變序號、每抽候選快照與結果、終點狀態及冪等紀錄。唯一性涵蓋每主播未完成場、每場每人報名、每場序號、同場 winner 及終點。分數查詢、缺席扣分、歷史與權限均帶主播歸屬；不可假設歷史觀眾只在當場名單內。
- 需設計可恢復、中斷後可安全重試的狀態轉移，不能提早釋放名額或讓部分結算可被再次執行。報名、暫停、停用、退出、抽選、結束與取消競態以伺服端原子提交順序及條件保護；延遲請求須核對確切場次與規則。
- D1 官方能力及實際隔離環境整合測試須驗證原子 batch、條件更新/CAS、約束、快照和 winner 更新及終點方案；不假設跨獨立請求或遠端 OAuth 可同一交易，不靠 isolate 記憶體鎖。若 D1 不能保證不變量，停止並重新設計，不宣稱可行。實際 SQL、索引、分批與恢復方案待技術設計及驗證。
- 已完成場次詳細報名、抽選、候選與聯絡歷史保留 90 天後清理；取消歷史保留至到期。**負責人已確認（#4，政策而非實作完成）：**正常場次從正常結算全部完成時起算 90 天；取消場次從取消恢復全部完成時起算 90 天，不從提出結束或取消請求時起算。未結束或結算／恢復未完成資料受保護；分數及正確性所需最小冪等資料持續保留。清理須冪等且防延遲請求重結算；不提供自助刪除 UI/API/佇列。不代表免除法律義務，上線前確認隱私告知與必要人工聯絡。

## 6. 容量及交付計畫

主要容量測試為單場 500 報名、累積歷史觀眾超過 1,000；初期可能只有一位主播，壓測另涵蓋五主播並行各 500、每場連續抽 20 人。均為測試情境，不是硬上限或典型使用量，也不是已通過承諾。量測每抽快照、索引、歷史、D1 讀寫與結算時所有相關歷史觀眾，包含共用免費額度；不截斷舊分數以迎合測試。

1. **設計及初始化：**確認官方 Workers、D1、Discord 能力與免費額度；設計資料鍵、索引、權限、狀態機、恢復、清理及 API 契約。以隔離測試資料開發，secret 不入測試 fixture。建立專案與測試工具需另依後續授權執行。
2. **核心規則：**先寫失敗測試再實作身份授權、場次及規則鎖、報名/退出、快照抽選、分數、結算與取消；並發、故障注入及 D1 整合測試驗證不變量。解析公式及可重現模擬分開記錄，不能以模擬取代安全亂數或實測。
3. **功能 MVP：**完成上述所有功能、90 天清理、鳴潮風格介面和簡單結果揭曉；驗證手機、鍵盤、錯誤與重試、權限、隱私及免費額度。**負責人已確認（#6，政策而非素材實作完成）：**先採原創介面幾何與授權清楚的字型及素材；在取得使用依據前，不使用鳴潮官方角色、Logo、圖片或音效。使用素材前須確認並保留其適用授權及使用條件的證據；目前不宣稱已取得任何官方素材授權。不得為本決策額外產生付費素材。
4. **第二階段：**負責人已確認（#7，延期決策而非實作完成）：完成 MVP 後再決定角色動畫的形式、範圍與素材，暫不製作角色動畫，不阻擋 MVP；尚未核准任何動畫方案，#17 的動畫實作仍待後續決定及追蹤。若後續決定製作，素材須遵守 #6，且只揭曉持久化結果，支援跳過、減少動態效果及中斷後不重抽。
5. **部署準備：**記錄真實測試與限額量測，隱私政策與 OAuth 設定確認。部署、建立 Git repo、commit 或任何付費變更均不在此次文件工作授權內；部署須另獲授權。

## 7. 驗收清單（待實際執行）

所有項目均為未執行的功能驗收，不因文件整理而通過。每項須保留實際測試方式、輸出與限制。

- [ ] **AC-01**：兩主播同時活動，同觀眾 A 的報名、抽中、分數和結算不改 B；偽造 ID 無法跨環境讀寫。
- [ ] **AC-02**：驗證伺服器配置的 Discord ID 才有管理權；未配置、未登入或不符 ID 均不得進入管理頁或呼叫管理操作。管理者在非公開受限頁以 Discord ID 核准主播，未核准者登入不得取得主播資格；可停用、讀用量，不能代抽、改分、結算或讀私有名單/聯絡；無公開申請按鈕、API、佇列、通知、代理及小幫手。
- [ ] **AC-03**：停用先提交時拒絕開場、報名、抽選；原主播仍能讀必要資料及收尾，停用不自動結束或刪除；並發測試提交先後。只有管理者明確重新核准才能恢復資格；驗證全部資料及未完成場次保留、不自動開場，重新啟用後仍有未完成場次時不得開新場，終點全部完成後才可開新場；無未完成場次時也不自動開場。
- [ ] **AC-04**：同主播並發開場至多成功一場，paused 占位，結算或恢復未完成不能新開；不同主播可並行。
- [ ] **AC-05**：暫停拒新報名但允許既有候選抽選及未中者退出；與報名競態一致；恢復沿用場次及序號。
- [ ] **AC-06**：主播/觀眾關頁、登出、斷線、逾時不改場次或資格；open 離線仍收報名，重新登入接回本場，無心跳。
- [ ] **AC-07**：鎖定規則開場後包括暫停皆不能修改；取消恢復後新場名單為空、重新查群及從 1 排序；舊場與 OAuth 回來的遲到請求不默報新場。
- [ ] **AC-08**：Discord 僅必要 scope；群限制啟用時測成功、非成員、pending、授權失效、429、故障；故障不放行、不誤稱未加入。報名後退群仍有效、下場重查。群限制關閉時，不要求群成員資格、不發起群成員查詢，也不因本次報名要求新增 `guilds.members.read` 授權；既有其他環境所需授權不因此失效。
- [ ] **AC-09**：退出不可重報、不加不扣；退出先提交不入後續抽選，中獎先提交拒絕退出；不得代退出、手動剔除或指定個人權重 0。
- [ ] **AC-10**：每抽快照一致，晚報下一抽；安全亂數、同鍵重試返回原結果、不同鍵並發及中斷重試不重複 winner；結果與歸零一致，聯絡失敗不重抽。
