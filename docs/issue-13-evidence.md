# Issue #13 本機切片證據（未驗收）

本機以 migration 0011 增加場次狀態版本，不重建活動或報名資料；主播以場次 ID、規則及狀態版本 CAS 暫停／恢復。報名與退出各以單一條件式 SQL 保護；退出保留原序號與紀錄，候選計數只含 registered。本人退出不改分數。未知結果讀取原場而不自動重送。

本機隔離 workerd/D1 測試涵蓋重試、權限、CSRF、暫停退出、終態及透過 HTTP 同時發送暫停與報名／退出；此為重疊請求，不代表已注入每個 SQL 提交邊界。Ego Chromium 合成資料在獨立 19681 fixture 走過開場、暫停、觀眾報名按鈕停用、恢復、報名、本人退出及重新載入；原序號 1 保留、人數 1→0，不可重報。此測試未使用真 Discord 或真帳號。

補驗：0010 建立不同主播的 open／paused 活動、registered／withdrawn、群證明、預設值、分數與基線，逐列逐欄比較 0011 前後；新增狀態版本均為 0，負值受約束拒絕。本機 HTTP 兩個相同版本的恢復請求重疊：一個 200、一個 409，精確目標版本只增加一次，另一主播場次不變。這些不是所有 SQL 提交邊界的驗證。

Ego 合成 fixture（19683）以鍵盤 Enter 報名序號 1；CDP 模擬 touch 退出，確認對話框後伺服器讀回退出、刷新仍為原序號且隱藏報名。這不是實體裝置；該次 mobile 模擬的 layout viewport 實測為 1006 CSS px，不能算窄視窗驗收。

補充回歸：以實際 public JS 的 Node 最小 DOM 測試重現三項卡死，修復前 3 個預期斷言均 RED，修復後 GREEN；另驗重新確認後「重新讀取場次」不再殘留 disabled。Ego Chromium／本機 19692、19693 合成 fixture 實測：暫停、恢復各鍵盤 Enter 一次，worker 提交後截斷回應本文、首次精確 GET 強制 503，再由按鈕讀取原場；每次 1 PUT、2 GET，狀態版本 0→1→2。退出同樣 1 POST、2 次原場 self GET，DB 為 withdrawn 且序號保留。新場載入時故意令原場讀取失敗，再按重新確認退出：新場報名按鈕恢復、原場 withdrawn、新場無報名及無額外 POST。主播無 current 時仍可確認原場，之後新場狀態不變。fixture 終結是直接修改合成 D1 的測試鉤子，不是產品取消功能。

Ego CDP 確認 innerWidth 與 clientWidth 均為 390 CSS px 後以 touch 事件報名，後續讀回揭露退出按鈕；此為模擬，非實機。提交後截斷的是已發送 HTTP 狀態與部分本文，不是完全無回應：初次試驗在未送 headers 即斷線時 Chrome 自動重送同一 PUT（第二次 409）；故不能把本次證據稱為完全無回應也無傳輸層重送。自動測試的 DOM 是最小替身，真 DOM 交互為上述 Ego 手動驗證，不是自動瀏覽器 suite。fixture 僅在 loopback 且三個 QA flag 明確啟用時暴露注入功能，未改 production router。

補充自動回歸：相同狀態版本的重複 PUT 經 CAS 僅一次改變狀態；最小 DOM 以 409、首次精確讀取 503 再讀取成功驗證待確認保留與保守顯示。這些分別驗證伺服器與客戶端邏輯，並非完整斷線及 Chrome 重送的端到端自動測試，不能代表所有網路故障。
